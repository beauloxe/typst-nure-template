# Оформлення тексту

Усе нижче працює після `#show: style.dstu` (див. [Лабораторна](lab.md#оформлення-styledstu)). Ви пишете звичайну розмітку [Typst](https://typst.app/docs/reference/syntax/), а оформлення за ДСТУ 3008:2015 застосовується саме.

## Сторінка й шрифт

- А4, поля: верхнє й нижнє 20 мм, ліве 25 мм, праве 10 мм; номер сторінки вгорі праворуч.
- Times New Roman 14 pt, вирівнювання за шириною, абзацний відступ 1,25 см, без переносів.
- Код -- Courier New 11 pt.

Якщо Times New Roman чи Courier New немає в системі, використовуються Liberation Serif і Liberation Mono, а Typst попереджає про відсутній шрифт. На Linux їх дає пакет `ttf-mscorefonts` (`ttf-mscorefonts-installer`) або аналог у вашому дистрибутиві.

## Заголовки

```typst
= Аналіз предметної області     // 1 АНАЛІЗ ПРЕДМЕТНОЇ ОБЛАСТІ -- з нової сторінки, по центру
== Огляд аналогів                // 1.1 Огляд аналогів
=== Перший аналог                // 1.1.1 Перший аналог

#utils.nheading[Вступ]          // ВСТУП -- без номера, але у змісті
```

Заголовки першого рівня завжди починаються з нової сторінки і пишуться великими літерами. Нумерація рисунків, таблиць, формул і лістингів скидається з кожним розділом: «Рисунок 2.1» -- перший рисунок другого розділу.

Коли заголовок іде одразу після іншого заголовка, між ними виходить подвійний інтервал; приберіть його через `#v(-spacing)` (потрібен імпорт `#import style: spacing`):

```typst
== Хід роботи
#v(-spacing)
=== Підготовка
```

## Списки

```typst
+ перший пункт      // а) перший пункт
+ другий пункт      // б) другий пункт
  + вкладений       //    1) вкладений
- маркер            // – маркер
```

Нумеровані списки першого рівня позначаються літерами української абетки, вкладені -- цифрами з дужкою, марковані -- тире.

## Рисунки

Найпростіше -- `utils.img`: підпис, джерело і мітка для посилання формуються самі.

```typst
#utils.img(path("figures/scheme.png"), [Схема роботи])
// Рисунок 1.1 – Схема роботи (рисунок виконано самостійно)

#utils.img(path("figures/net.png"), [Топологія мережі], "cisco.com", width: 80%)
// Рисунок 1.2 – Топологія мережі (за даними cisco.com)

#utils.img(path("figures/logo.png"), [Логотип], (), label: <logo>)
// Рисунок 1.3 – Логотип
```

- Третій аргумент -- джерело: не вказано (`none`) -- «(рисунок виконано самостійно)»; рядок -- «(за даними …)»; `()` -- без примітки.
- Мітка утворюється з назви файлу і теки: `figures/scheme.png` → `<figures_scheme>`, `scheme.png` → `<scheme>`. Свою мітку задає `label: <...>`, а `label: none` її прибирає.
- Інші аргументи (`width`, `height`, `fit`) передаються в `image`.
- Назву файлу треба обгорнути в `path()`, див. [Шляхи до файлів](#шляхи-до-файлів).

Без `utils.img` -- звичайний `figure` Typst, оформлення буде те саме:

```typst
#figure(image("figures/scheme.png", width: 80%), caption: [Схема роботи]) <scheme>
```

## Таблиці

Невелика таблиця -- через `figure`:

```typst
#figure(
  table(
    columns: 3,
    [Параметр], [Значення], [Одиниці],
    [Частота], [12], [МГц],
  ),
  caption: [Параметри мікроконтролера],
) <params>
```

Назва «Таблиця 1.1 – Параметри мікроконтролера» розміщується над таблицею.

Таблиця, що може не вміститися на сторінку, -- через `dstu-table`. На кожній наступній сторінці вона повторює шапку і пише «Продовження таблиці 1.1», а на останній -- «Кінець таблиці 1.1», як вимагає ДСТУ:

```typst
#dstu-table(
  caption: [Результати вимірювань],
  columns: (1fr, 2fr, 2fr),
  header: ([№], [Напруга, В], [Струм, мА]),
  tag: "measurements",
  [1], [3.3], [12],
  [2], [5.0], [18],
  // ...
)

Результати наведено в таблиці @measurements.   // ... в таблиці 1.1.
```

- `caption`, `columns`, `header` обов'язкові; `header` -- масив комірок шапки.
- `tag` -- назва мітки рядком; посилання `@measurements` дає лише номер («1.1»), тож слово «таблиця» пишіть самі.
- Решта аргументів (`align`, `stroke`, …) передається в `table`.

У межах однієї роботи користуйтеся чимось одним: `figure(table(...))` і `dstu-table` нумеруються окремо, тож разом вони дадуть дві «Таблиці 1.1».

## Формули

```typst
$ E = m c^2 $ <einstein>

Обчислимо за @einstein[формулою] ...   // Обчислимо за формулою (1.1) ...
```

Виносні формули нумеруються за розділами справа: (1.1), (1.2). Формули в рядку (`$x^2$`) не нумеруються.

## Код

````typst
```c
int main(void) {
  return 0;
}
```
````

Блок коду виводиться шрифтом Courier New 11 pt з відступом. Лістинг з підписом -- через `figure`:

````typst
#figure(
  ```bash
  for f in *.txt; do wc -l "$f"; done
  ```,
  caption: [Підрахунок рядків у файлах],
) <count-lines>
````

Назва «Лістинг 1.1 – Підрахунок рядків у файлах» розміщується над кодом.

Код з файлу:

```typst
#raw(read("assets/sample.c"), lang: "c", block: true)
```

Код у рядку (`` `ls -la` ``) за ДСТУ не оформлюється окремим шрифтом: шаблон виводить його звичайним текстом у лапках -- «ls -la».

## Посилання

На рисунки, таблиці (`figure`), формули й лістинги посилаються через мітку:

| Розмітка | Результат |
| --- | --- |
| `@figures_scheme` | Рисунок 1.1 |
| `@figures_scheme[рисунку]` | рисунку 1.1 |
| `@params` | Таблиця 1.1 |
| `@einstein` | Рівняння (1.1) |
| `@einstein[формулою]` | формулою (1.1) |
| `@count-lines` | Лістинг 1.1 |
| `@measurements` (`dstu-table`) | 1.1 |

Слово в дужках замінює підпис -- так зручно узгоджувати відмінки: «на @figures_scheme[рисунку]», «у @params[таблиці]».

## Перелік джерел

Джерела записуються у файл `bibl.yml` (формат [Hayagriva](https://github.com/typst/hayagriva/blob/main/docs/file-format.md)):

```yaml
mysql:
  type: Book
  title: MySQL Language Reference
  author: Ab M.
  publisher: MySQL Press
  date: 2004
  page-total: 600

go:
  type: Web
  title: The Go Programming Language
  author: The Go Programming Language
  url:
    value: https://go.dev/
    date: 2024-12-10
```

Перевірено оформлення типів **Book** (книги: автор, назва, видавництво, рік, кількість сторінок) і **Web** (вебресурси: назва, автор чи організація, URL, дата звернення). Інші типи не перевірено на відповідність стандарту, не раджу їх використовувати.

У тексті: `@go` → [1]. Перелік виводиться там, де стоїть:

```typst
#dstu-bibliography(path("bibl.yml"), style: "3008")
```

| Аргумент | Значення |
| --- | --- |
| `style` | `"3008"` -- ДСТУ 3008:2015, `"8302"` -- ДСТУ 8302:2015, або власний CSL-стиль (`read("my.csl", encoding: none)`) |
| `title` | Заголовок, за замовчуванням «Перелік джерел посилання» |
| `full` | `true` (за замовчуванням) -- усі записи з файлу; `false` -- лише процитовані |

Перелік джерел ставиться перед додатками.

## Додатки

```typst
#show: style.appendices

= Код програми
#raw(read("assets/main.c"), lang: "c", block: true)

= Знімки екрана
#utils.img(path("figures/screen.png"), [Головне вікно])
```

Усе після `#show: style.appendices` -- додатки. Кожен заголовок першого рівня починає новий додаток з нової сторінки: «ДОДАТОК А», нижче назва. Підрозділи нумеруються «А.1», рисунки, таблиці й формули -- «Рисунок А.1», «Таблиця А.1».

Додатки можна тримати в окремому файлі: `#style.appendices(include "chapters/appendices.typ")`.

## Шляхи до файлів

Рядок зі шляхом Typst шукає відносно того файлу, де стоїть виклик функції. Для ваших власних викликів це зручно: `image("figures/a.png")` у `main.typ` знайде `src/figures/a.png`.

Але якщо передати рядок у функцію **пакунка** (`utils.img`, `dstu-bibliography`, `bib-path:` у рецептах), файл шукатиметься в теці пакунка, а не у вашій роботі. Тому назви файлів, які передаєте в пакунок, обгортайте в `path()` -- такий шлях пам'ятає, з якого файлу його записано:

```typst
#utils.img(path("figures/a.png"), [Рисунок])
#dstu-bibliography(path("bibl.yml"))
```

`utils.img` на звичайний рядок відповідає помилкою з підказкою. Тип `path` з'явився в Typst 0.15, тому пакунок потребує цієї версії.
